# Paper Room

ร้านภาพพิมพ์ภาษาไทยสำหรับพอร์ต Full-stack สร้างด้วย Next.js App Router, TypeScript และ SQLite ภาพพิมพ์ทั้ง 6 แบบเป็นไฟล์ SVG ภายในโปรเจกต์

## เริ่มในเครื่อง
ใช้ Node.js 24 ขึ้นไป แล้วรันจากโฟลเดอร์โปรเจกต์

```sh
npm ci
npm run dev
```

เปิด http://localhost:3000 สำหรับโหมด production ใช้ `npm run build` แล้ว `npm start`

## บัญชีลูกค้าและคนขาย
ลูกค้าสมัครด้วยอีเมลและรหัสผ่านผ่านปุ่ม **เข้าสู่ระบบ** ระบบจะพากลับไปตะกร้าเมื่อสมัครระหว่างสั่งซื้อ เปิด **บัญชีของฉัน** เพื่อดูออเดอร์ที่ผูกกับบัญชีนี้ได้จากทุกเบราว์เซอร์

เจ้าของร้านสร้างบัญชีคนขายจากเครื่องที่รันเซิร์ฟเวอร์ ใช้อีเมลใหม่ แล้วเก็บรหัสผ่านแบบสุ่มที่คำสั่งแสดง

```sh
npm run seller -- owner@example.com
```

## ทดลองสองบทบาท
1. ในเบราว์เซอร์ปกติ สมัครบัญชีลูกค้าแล้วสั่ง Slow Bloom ขนาด A3 จำนวน 2 ชิ้น ยอดรวม 1,180 บาท
2. เปิดบัญชีของฉันเพื่อดูใบยืนยัน
3. ในหน้าต่างส่วนตัว เข้าสู่ระบบด้วยบัญชีคนขาย เปิดหลังร้านแล้วเทียบเลขคำสั่งซื้อ
4. ในแท็บคำสั่งซื้อ กด **เริ่มเตรียมสินค้า** แล้ว **ยืนยันว่าจัดส่งแล้ว** ลูกค้าเปิดบัญชีของฉันอีกครั้งเพื่อดูสถานะล่าสุด
5. ปรับสต็อก A3 ในหลังร้าน จากนั้นโหลดหน้าร้านของลูกค้าใหม่เพื่อตรวจผล

## การทำงาน
API ตรวจบทบาทจากเซสชันใน SQLite ทุกครั้งที่อ่านออเดอร์หรือแก้ไขข้อมูล บัญชีลูกค้าเห็นเฉพาะออเดอร์ของตนเอง คนขายดูออเดอร์ของร้านและแก้สต็อกส่วนกลางได้ รหัสผ่านใช้ scrypt กับ salt รายบัญชี คุกกี้ HttpOnly มีอายุ 7 วัน เซิร์ฟเวอร์เก็บแฮชของโทเคนและเพิกถอนเมื่อออกจากระบบ

ฐานข้อมูลอยู่ใน data/prints.sqlite ออเดอร์เดโมเดิมที่แยกตามเบราว์เซอร์ยังเก็บไว้ในฐานข้อมูล ระบบบัญชีเริ่มด้วยสต็อกร้านชุดใหม่และแสดงเฉพาะออเดอร์ที่มีเจ้าของบัญชี

เซิร์ฟเวอร์ตรวจราคาและจำนวนเอง บันทึกออเดอร์และหักสต็อกใน SQLite transaction เดียว การส่ง checkout token เดิมซ้ำจะได้ใบยืนยันเดิม เว็บจำลองขั้นตอนสั่งซื้อ ไม่มีการเรียกเก็บเงินจริง

```sh
npm test
npm run build
```

## รันด้วย Docker

จากโฟลเดอร์โปรเจกต์ รันด้วย Docker Compose แล้วเปิด http://127.0.0.1:3001 พอร์ตนี้เปิดคู่กับเว็บที่รันบนพอร์ต 3000 ได้

```sh
docker compose up --build -d --wait
docker compose exec web npm run seller -- owner@example.com
```

ฐานข้อมูลใน Docker เริ่มแยกจากฐานข้อมูลบนเครื่อง และเก็บบัญชี สต็อก และออเดอร์ใน named volume ชื่อ `shop-data` หยุดเว็บด้วย `docker compose down` แล้วเปิดอีกครั้งด้วย `docker compose up -d --wait` เพื่อใช้ข้อมูลเดิม หากต้องการเปลี่ยนพอร์ต ให้ตั้ง `PAPER_ROOM_PORT` ก่อนเปิดเว็บ

## GitHub Actions

เมื่อ push โปรเจกต์นี้ไปยัง GitHub หรือเปิด pull request งาน **Paper Room CI** จะรัน unit tests ระหว่าง build อิมเมจ จากนั้นเปิดเว็บ ตรวจหน้าร้านและ API และตรวจว่าบัญชีคนขายยังอยู่หลังสร้างคอนเทนเนอร์ใหม่ ดูผลได้ในแท็บ Actions ของ repository

## ตรวจความปลอดภัยใน CI

CI รันทดสอบผ่าน HTTP กับเซิร์ฟเวอร์ Next.js และฐานข้อมูลชั่วคราว ตรวจว่าผู้ใช้ที่ยังไม่เข้าสู่ระบบได้ 401 ลูกค้าที่ปลอมบทบาทคนขายได้ 403 และคำขอที่ถูกปฏิเสธไม่มีผลต่อสต็อกหรือสถานะออเดอร์ รวมถึงตรวจการแยกออเดอร์ระหว่างลูกค้า ต้นทางของคำขอ และการเพิกถอนเซสชันหลังออกจากระบบ

รันเทสต์ HTTP ในเครื่องหลัง build หรือผ่านอิมเมจ Docker ได้ดังนี้

```sh
npm run build
npm run test:http
# หรือ
docker compose build web
docker compose run --rm --no-deps web npm run test:http
```

Trivy สแกนอิมเมจที่ build แล้วและเก็บรายงานทุกระดับความรุนแรงเป็น artifact ชื่อ **trivy-report** เป็นเวลา 14 วัน CI จะไม่ผ่านเมื่อพบ Critical ที่มีเวอร์ชันแก้แล้ว การดาวน์โหลดฐานข้อมูลหรือการสแกนล้มเหลวก็ทำให้งานไม่ผ่าน รายการระดับอื่นและ Critical ที่ยังไม่มีวิธีแก้จะอยู่ในรายงานสำหรับตรวจติดตาม

GitHub Actions ตรึงด้วย commit SHA และ Dependabot ตรวจอัปเดต npm, Docker base image และ Actions รายสัปดาห์ เปิดรายงานและผลตรวจจริงได้ในแท็บ Actions หลัง push โปรเจกต์ขึ้น GitHub
